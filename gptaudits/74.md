## Причина и изменение поведения

Главная ошибочно относила `price_delta == 0` к красному росту: обе функции стиля проверяли только отрицательное значение. Ноль теперь нейтрален; рост красный, снижение зелёное; отсутствие текущей цены и отсутствие базы сравнения имеют отдельные подписи. Названия отслеживаемых товаров ведут в `/product/{id}`. Ошибка API больше не выглядит как пустой список. Описание блока говорит о последних доступных данных и Advanced-уведомлениях.

Отдельный блок «Отслеживание устройств» на главной показывается только при активном Advanced. Поиск устройства, подписка/удаление и ссылка на `/devices/{model_key}`; кнопка подписки также на странице устройства. API list/put/delete защищены `require_feature("device_tracking")`. Проверяется актуальная подписка, а не только сохранённое имя тарифа.

`tracked_devices` хранит подписки с уникальностью user/device. `tracked_device_products` запоминает уже доступные товары при подписке; периодический `sync_prices` обнаруживает новые доступные канонические товары через Product → Cluster → Device. Это учитывает поздний matching, не уведомляет о старом каталоге и не повторяет событие для уже замеченного товара. Блокировка подписки и уникальные ключи защищают параллельные scans. Используется существующая in-app доставка. Проверяется entitlement и при сканировании; при возврате Advanced обнаруживаются ранее не сообщённые новые товары. Новые магазины/повторное появление того же канонического товара не считаются новой запчастью.

Миграция `20261113_device_tracking` добавляет таблицы и расширяет тип уведомлений. Откат удаляет только уведомления нового типа перед восстановлением старого CHECK; это намеренная потеря данных новой функции при rollback. Изменения рабочей БД и развёртывание не выполнялись.

Frontend: 12 component tests passed, lint, TypeScript и production build завершились успешно после финальной правки состояния без базы сравнения.
