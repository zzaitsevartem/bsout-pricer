# Сессия 57 — оценка источника на поисковых карточках (2026-11-05)

По запросу пользователя чтение поручено bscout_reader (профиль Luna / medium), заключение сформировано главным агентом. Реализация и оркестрация реализации ожидают следующего задания. Приложение не меняли, тесты и live UI не запускали.

Текущий каталог группирует StoreOffer по каноническому Product. Связь предложения с магазином и URL уже есть в БД (products/model/product.py), но каталог отдаёт store_slugs и агрегаты без выбранного предложения/магазина (products/schema/comparison.py:54-70; comparison_service.py:48-109,147-165). CatalogResultCard показывает минимальную цену и количества без источника. OfferResultCard уже отображает магазин конкретного предложения, если store присутствует.

Рекомендация: источник у цены «от» — магазин конкретного предложения с минимальной розничной ценой среди предложений, прошедших текущие фильтры; ссылка ведёт на это предложение. При равенстве цен нужен стабильный выбор. Карточки без предложений должны явно показывать отсутствие источника. Оптовый минимум и изображение агрегируются независимо и могут иметь другие источники: не приписывать их автоматически выбранному розничному предложению. Если пользователь имеет в виду авторство фото/описания, потребуется отдельный объём работ.

Оценка главным агентом: средняя сложность, локальное сквозное изменение backend query/API + frontend schema/card + регрессионные проверки; ориентир 3–5 часов с проверкой живого API/UI, без миграции БД при текущей модели. Проверить фильтры, равные цены, несколько магазинов, отсутствие предложений и отображение в обеих разновидностях карточек. Существующие dirty-изменения пересекаются с предполагаемыми файлами, их нужно сохранить и согласовать при реализации. Никаких коммитов, перезапусков сервисов и чтения .env не выполнялось.
