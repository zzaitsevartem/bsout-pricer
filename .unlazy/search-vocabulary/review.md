# Независимый обзор: search vocabulary

Дата: 2026-11-06. Четыре прохода: область изменений; токены, границы и бюджет; общие SQL-потребители и фильтры/порядок; затем сверка контрактных строк с тестами и runtime evidence.

## Вывод

Блокирующих дефектов в просмотренном production diff не обнаружено. Расширение запроса сохраняет AND между токенами и OR только между вариантами одного токена. Оно ограничивает новые кандидаты и оставляет исходный токен первым. Матрица тестов подтверждает заявленные примеры и отрицательные контроли. Утверждение о полном двустороннем транслите было бы неверным: поддерживаются только явно заданные группы написаний.

Изменённый production scope — `backend/src/modules/products/service/search_predicate.py`; `normalizer.py` и persisted data не менялись. Лимит — до 12 кандидатов на токен, включая исходный, и до 64 дополнительных кандидатов на запрос. Для N исходных токенов максимум равен `N + min(11N, 64)` кандидатам, то есть не выше `min(12N, N+64)`. В fuzzy-режиме добавляется максимум один similarity-клауз на подходящий буквенный кандидат: общее число клауз не выше `2 × [N + min(11N,64)]` (и, следовательно, `2N+128`); базовые N токенов сами по себе не ограничены бюджетом расширения.

## Спецификация

В `docs/technical-specification.md:325-336` уточнена тарифная политика: исправление fuzzy-опечаток остаётся только Advanced, а детерминированные эквивалентности раскладки, `е/ё` и подтверждённых вариантов латиницей доступны всем тарифам и не меняют отображаемый запрос.
