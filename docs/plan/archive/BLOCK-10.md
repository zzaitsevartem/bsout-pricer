## БЛОК 10 — Матчинг и сравнение цен (ядро ценности)

**Статус:** [x] 2026-07-25 · **P0** · Не требует сети

**Итог: сравнение цен между магазинами РАБОТАЕТ.** На 308 реальных офферах: 308 авто-связано, 0 unmatched, создано 128 канонических товаров и 95 кластеров. Приёмка по эталону из `data/fixtures/README.md` сошлась цифра в цифру (4 группы схлопнулись в один товар по 5 магазинов; 4 класса качества дисплея iPhone 13 остались разными товарами в одном кластере). Тесты 211 → 391.

**Организация:** 2 раунда по 2 параллельных агента в worktree. Матчер написан мной — агент раунда 2 упал на инфраструктурной ошибке API (не код).

**Проблема.** Блок 02 создал схему (`products`-канон, `clusters`, `store_offers.product_id`, `match_candidates`), но **логики матчинга нет вообще**: ничего не разбирает название на бренд/устройство/тип детали/качество, не создаёт канон, не связывает оффер с ним, не наполняет очередь модерации, не пересчитывает агрегаты. Итог: сравнить цену одной детали между магазинами невозможно — это и есть заявленная суть продукта. Флаг `is_cheapest` в API сейчас фикция (минимум по текущей странице выдачи).
