## 1. Резюме

Задача: попап, который появляется через 5 секунд на главной странице, предлагает **один бесплатный пробный поиск** и не даёт использовать его повторно (защита через Redis + cookie). Парсеры магазинов ещё не подключены, поэтому поиск возвращает **пустой результат** — это заглушка.

В ходе аудита требование было уточнено и расширено:

- после использования поиска — показывать уведомление «Зарегистрируйтесь, чтобы увидеть результат»;
- если пользователь случайно ушёл со страницы и не зарегистрирован — окно должно появляться снова;
- **после регистрации окно не должно появляться больше никогда**;
- пока пользователь не зарегистрирован — окно появляется при каждом визите.

**Вывод:** текущая реализация этому требованию **не соответствовала** (попап после использования поиска исчезал навсегда; кнопка/флоу регистрации отсутствовали). В ходе аудита логика была переделана (см. раздел 6 «Что исправлено»), но остались инфраструктурные ограничения (раздел 5) и смежные проблемы (раздел 7).

## 2. Область аудита (Scope)

**Входит:**

- Backend-модуль `src/modules/trial/` (controller, service, schema);
- интеграция с Redis через `RedisCache` + in-memory fallback;
- frontend-модель `src/models/trial/` (schema, service, hooks, index);
- виджет `src/widgets/TrialPopup/`;
- подключение к главной странице, анимации (`tailwind.config.ts`);
- флоу регистрации/входа как зависимость «попап больше не показывается»:
  - `src/models/auth/*`, страницы `/register` и `/login`;
- конфигурация: CORS, rate-limit, прокси `/api/*`, `docker-compose.yml`.

**Не входит:**

- сами парсеры магазинов (реестр пуст — возвращают пустые результаты);
- платёжная система, подписки, админка;
- остальные модули (products/search/users/stores/categories) — только в контексте влияния на trial-флоу.

## 3. Как это работает (сквозной поток)

### 3.1 Маршрутизация и прокси

```
Браузер (localhost:3000)
   │  GET /api/trial/status
   ▼
Next.js dev server
   │  next.config.mjs: rewrite /api/:path* → http://localhost:8000/api/:path*
   ▼
FastAPI (localhost:8000)
   ├─ CORSMiddleware        — разрешён только origin http://localhost:3000
   ├─ RateLimitMiddleware   — 120 запросов / 60 сек на IP (in-memory)
   └─ trial_router          — /api/trial/*
```

### 3.2 Backend: идентификация клиента (cookie)

`controller/trial.py → _get_or_create_client_id()`:

- читает cookie `bscout_trial_id`;
- если cookie нет — генерирует `uuid4()` и ставит cookie:
  - `httponly=True`, `samesite="lax"`, `path="/"`, `max_age=30 дней`;
- вызывается из **обоих** эндпоинтов (`GET /status`, `POST /search`).

### 3.3 Backend: флаг «поиск использован»

`TrialService`:

- ключ: `trial:search:{client_id}`;
- TTL: 30 дней (`60*60*24*30`);
- `is_used()` → `RedisCache.exists(key)`; при любой ошибке → падение в `_fallback_store` (dict в памяти процесса);
- `mark_used()` → `RedisCache.set(key, record, ttl=30d)`; при ошибке → запись в `_fallback_store`.

Запись: `{ used: true, used_at: ISO-8601 UTC, query: "..." }`.

### 3.4 Backend: эндпоинты

| Метод | Путь | Логика |
|---|---|---|
| `GET` | `/api/trial/status` | выдаёт/создаёт cookie → `available = !is_used(client_id)` → `{ available, client_id }` |
| `POST` | `/api/trial/search` | если `is_used` → **403** `"Trial search has already been used"`; иначе `mark_used` → `{ results: [], total: 0, page: 1, per_page: 20, query }` |

> `results` всегда пустой: парсеры не подключены (`parser_manager` без регистраций). Это сознательная заглушка «поиск работает, но данных ещё нет».

### 3.5 Frontend: попап

`TrialPopup` (client-компонент, смонтирован в `src/app/page.tsx`):

1. **Загрузка статуса:** `useTrialStatus()` → `GET /api/trial/status`. Query-ключ `['trial','status']`, `staleTime: Infinity`, `retry: false`.
2. **Показ:** таймер 5 сек → `isOpen = true`, **только если** пользователь не зарегистрирован (`localStorage.access_token` отсутствует).
3. **Два состояния окна:**
   - поиск ещё не использован (`status.available === true` и запроса не было) → **форма поиска**;
   - поиск использован (`available === false` ИЛИ только что отправлен запрос) → **экран «Зарегистрируйтесь, чтобы увидеть результат»** с кнопкой `Зарегистрироваться` (→ `/register`) и ссылкой `Войти` (→ `/login`).
4. **Отправка:** `POST /api/trial/search` → `useTrialSearch` → `onSuccess` инвалидирует `['trial','status']` → сервер подтверждает `available:false`. При 403/ошибке сети — сообщение об ошибке в форме.
5. **Закрытие:** × / клик по фону / `Escape`. Механизма «закрыто навсегда» больше **нет** — при следующем визите (если не зарегистрирован) окно появится снова.
6. **Анимации:** `trialFadeIn` (фон 0.3s), `trialPop` (окно 0.5s cubic-bezier), `glowPulse` (золотое свечение иконки, 2.4s) — определены в `tailwind.config.ts`.

### 3.6 Frontend: определение «зарегистрирован»

- **Источник истины:** наличие `access_token` в `localStorage` (читается на каждом рендере и внутри таймера).
- Токены сохраняются: `useLogin` и (после правок) `useRegister` → `localStorage.setItem('access_token' | 'refresh_token', ...)`.
- axios-интерцептор (`src/shared/api/axios.ts`): подставляет `Authorization: Bearer <access_token>` в каждый запрос; на 401 пробует `POST /api/auth/refresh`; при неудаче чистит токены и редиректит на `/login`.
- После успешной регистрации происходит редирект на `/` → при рендере попапа `access_token` уже есть → попап **не показывается**.

### 3.7 Регистрация

- Страница `/register` (после правок): контролируемые поля, валидация `registerRequestSchema` (zod), проверка совпадения паролей, вызов `POST /api/auth/register` → `TokenResponse` (`access_token`, `refresh_token`, `token_type`).
- `useRegister.onSuccess` → сохраняет токены в localStorage, инвалидирует `['user']`, `router.push('/')`.
- Backend `/api/auth/register`: проверяет email на дубликат (409), создаёт пользователя в **PostgreSQL**, возвращает токены. **Требуется БД.**

## 5. Ограничения (инфраструктура)

1. **На машине нет Docker, PostgreSQL и Redis.**
   - `docker-compose.yml` есть в корне репозитория (AGENTS.md ошибочно ссылается на `docker/docker-compose.yml`), но поднять его нечем.
   - `psql`/сервер PostgreSQL не установлены и не запущены (порт 5432 пуст).
   - Redis недоступен → `TrialService` пишет во **временный in-memory dict**.
2. **Пробный флаг не переживает рестарт бэкенда.** При каждом рестарте `_fallback_store` очищается → пользователь может использовать пробный поиск заново. С реальным Redis (TTL 30 дней) этого не будет.
3. **Регистрация не может завершиться без БД.** `/api/auth/register` пишет в PostgreSQL; без неё — ошибка соединения. Флоу «зарегался → попап исчез» E2E проверить сейчас нельзя (фронтенд-логика корректна, ошибка формы обрабатывается).
4. **Бэкенд запущен вручную, процесс эфемерный:**
   `C:\Users\pphlo\AppData\Local\Temp\opencode\bsvenv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8000`
   - если упал/перезапущен ПК — попап перестанет появляться (статус-запрос будет падать, `retry: false` → нет данных → нет попапа).
5. **`python` в PowerShell не работает** (код 9009). Рабочие варианты: `py` или полный путь к venv.
6. **Прокси жёсткий:** `/api/*` → `http://localhost:8000/api/*` (захардкожено в `next.config.mjs`).
7. **CORS** разрешает только `http://localhost:3000` — для продакшен-домена нужно расширять.

## 7. Найденные проблемы

### Критично

1. **`/login` — статическая форма, вход не работает.**
   `frontend/src/app/login/page.tsx` не имеет обработчика `onSubmit`, поля не контролируемые, `useLogin` нигде не вызывается. Следствие: зарегистрированный пользователь, который очистил localStorage или сменил браузер, **не сможет войти** и снова увидит попап. Рекомендуется подключить форму по аналогии с `/register`.

2. **Нет переноса «использованного trial» на аккаунт.**
   Флаг живёт только на анонимном `client_id` (cookie). После регистрации зарегистрированный пользователь **не получает результат** своего пробного поиска (заглушка так и остаётся пустой), а связка «аккаунт ↔ использованный запрос» отсутствует.

### Высокая

3. **Fallback в памяти не выполняет бизнес-требование «один раз».** Рестарт бэкенда → `_fallback_store` пуст → пробный поиск снова доступен. Лечится только реальным Redis.
4. **Определение «зарегистрирован» по `localStorage.access_token` без проверки валидности.** Токен живёт 15 минут; если `refresh` не сработал (или нет сети), попап будет скрыт для де-факто незалогиненного пользователя. Надёжнее проверять через `GET /api/users/me`.
5. **Токены в localStorage — уязвимость к XSS** (стандартная практика проекта, но при внедрении скрипта токены похищаются). Более безопасно — httponly-cookie.

### Средняя

6. **`useTrialStatus` с `staleTime: Infinity`.** Между инвалидациями статус кэшируется; при мультивкладочной сессии возможна рассинхронизация (вторая вкладка покажет устаревший `available`). При full-reload не проявляется.
7. **Попап может раздражать:** при каждом визите главной (пока не зарегистрирован) через 5 сек. Нет частотного лимита показа (например «1 раз в сутки»).
8. **Rate-limit глобальный и in-memory** (`RateLimitMiddleware`, `defaultdict` по IP): 120 запросов/мин на все эндпоинты; после рестарта счётчики сбрасываются; в мультипроцессном деплое каждый воркер считает отдельно.

### Низкая / Инфо

9. **Cookie без `secure`** (dev, нет HTTPS) — при выводе в прод настраивать.
10. **`/api/trial/search` всегда возвращает пусто** до подключения парсеров; на фронте нет состояния «данные появятся позже», только заглушка.
11. **`TrialSearchResponse` зависит от `products.schema.ProductResponse`** — изменения контракта товара затронут trial-ответ.
12. **Тест-признак регистрации — строка в localStorage**, а не состояние из effector-стора `$isAuth`/`$user` (`src/shared/config/store.ts` существует, но не интегрирован).

## 8. Рекомендации (приоритет)

1. **Поднять инфраструктуру** (Docker Desktop или локальные PostgreSQL+Redis), применить `docker-compose.yml` из корня. Проверить миграции: `alembic upgrade head`.
2. **Подключить форму `/login`** (контролируемые поля + `useLogin` + редирект) — сейчас вход невозможен.
3. **Перенести trial-флаг на аккаунт:** при регистрации сохранить `client_id`/запрос к `user_id`, чтобы зарегистрированный пользователь получил результат своего пробного поиска, а попап не появлялся.
4. **Определять регистрацию по серверу** (`GET /api/users/me`), а не по наличию токена.
5. Рассмотреть **httponly-cookie** для токенов вместо localStorage.
6. Добавить лимит частоты показа попапа (например `sessionStorage` «показывать не чаще 1 раза в N часов» — но не «навсегда», чтобы не сломать требование №4 из чеклиста).
7. Для локальной отладки без Docker — при желании добавить в `database.py` фолбэк на SQLite (требует проверки Postgres-специфичных типов в моделях: `Numeric`, возможные `JSONB`/`UUID`).

## 9. Заключение

Функционально фича «пробный поиск + попап + регистрация» реализована в соответствии с уточнённым ТЗ: попап показывается через 5 сек, у незарегистрированных — при каждом визите, после использования поиска — экран «Зарегистрируйтесь, чтобы увидеть результат», после регистрации — исчезает навсегда. Сборка и линт чистые.

**Главный риск — не инфраструктурный код, а отсутствие окружения:** без PostgreSQL нельзя проверить регистрацию, без Redis флаг trial не переживает рестарт. Пока Docker не поднят, фичу можно демонстрировать в режиме «fallback», помня, что ограничения «один раз на браузер» и «зарегистрировался — окно пропало» в полном объёме заработают только после поднятия БД и Redis.
