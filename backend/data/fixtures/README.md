# Демо-датасет офферов (`demo_offers.json`)

Синтетический, но реалистичный набор товарных предложений пяти ставропольских магазинов
запчастей. Нужен для разработки и валидации **матчинга офферов в канонические товары**
(Блок 10), а также для демо сценария «сравни цену» без реального запуска парсеров.

Данные вымышленные: SKU, ссылки и цены не соответствуют настоящим каталогам магазинов,
но воспроизводят их манеру именования и порядок цен.

## Файл

- `backend/data/fixtures/demo_offers.json` — JSON-массив из **308** объектов, UTF-8, отступ 2.
- Инварианты файла закреплены тестом `backend/tests/integration/test_demo_fixture.py`
  (22 проверки). Файл правится руками; после любой правки прогоняйте тест.

## Формат записи

Единый формат импорта — плоский объект, ровно 12 полей, лишних ключей нет.

| Поле           | Тип             | Описание                                                                 |
| -------------- | --------------- | ------------------------------------------------------------------------ |
| `store_slug`   | str             | Магазин: `tgsm`, `profi`, `liberti`, `greenspark`, `divizion`             |
| `source_sku`   | str             | Артикул магазина. Уникален в пределах `store_slug`                        |
| `title`        | str             | Название как на витрине магазина — «грязное», в исходном написании        |
| `price_retail` | str (десятичн.) | Розничная цена в рублях, всегда `> 0`, формат `"4500.00"`                 |
| `price_opt`    | str \| null     | Оптовая цена, если есть; всегда строго меньше `price_retail`              |
| `price_old`    | str \| null     | Старая цена (зачёркнутая), если есть; всегда строго больше `price_retail` |
| `stock_status` | str             | `in_stock` \| `low` \| `out` \| `preorder` \| `unknown`                   |
| `stock_qty`    | int \| null     | Остаток, `>= 0`                                                           |
| `url`          | str             | Ссылка на карточку, домен соответствует `store_slug`                      |
| `image_url`    | str \| null     | Абсолютный `https://`                                                     |
| `description`  | str \| null     | Описание с витрины                                                        |
| `category`     | str \| null     | Категория как её называет сам магазин (не наш справочник)                 |

Поля 1:1 ложатся на `ParseResult`
(`backend/src/modules/parser/service/base.py`) и далее на `StoreOffer`
(`backend/src/modules/products/model/product.py`): `price_*` → `Decimal`,
`store_slug` → `Store.slug` → `StoreOffer.store_id`, уникальность
`(store_slug, source_sku)` соответствует `UNIQUE(store_id, source_sku)`.

## Как загрузить

Датасет намеренно не содержит кода импорта — загрузчик живёт отдельно. Ожидаемый путь:
прочитать файл → на каждую запись собрать `ParseResult` → вызвать
`ParserService.upsert_offer(db, store_id, result)`. Апсерт идемпотентен по
`(store_id, source_sku)`, поэтому повторная загрузка не плодит дубли, а обновляет цену и
пишет историю.

Тест датасета не зависит ни от БД, ни от эндпоинта импорта — он валидирует сам JSON.

```bash
cd backend
python -m pytest tests/integration/test_demo_fixture.py -q
```

## Трудные кейсы (заложены намеренно)

1. **Опечатка в типе детали** — `Диспелй для iPhone 14 копия` (profi). Должен попасть в ту же
   группу, что `Дисплей Apple iPhone 14 в сборе с тачскрином (Копия)` (tgsm) и
   `Экран Айфон 14 в сборе копия` (divizion).
2. **Опечатка в «аккумулятор» + кириллическая транслитерация модели** —
   `Акумулятор Ксиоми Редми Ноут 12 копия` (divizion) = `Аккумулятор Xiaomi Redmi Note 12 (Копия)`.
3. **Кириллическая «Х» вместо латинской «X» в модели** — `Дисплей Хонор 8Х в сборе копия`
   (divizion) = `Дисплей Honor 8X в сборе с тачскрином (Копия)` (tgsm) =
   `Дисплейный модуль Honor 8X (JSN-L21), аналог` (greenspark).
4. **Латиница вперемешку с кириллицей внутри слова** — `Дисплей для Айфон 13 оriginal (OLED)`
   (profi): «Айфон» кириллицей, «оriginal» с кириллической «о».
5. **Полная транслитерация типа детали** — `Akkumulyator iPhone 13 ORIG` (liberti).
6. **Только английский** — `Display iPhone 14 assembly Original` (liberti), без единого
   русского слова.
7. **Обратный порядок слов** — `S23 Galaxy Samsung дисплей ORIG (OLED)` (liberti): модель
   первая, бренд в середине.
8. **Модельный код вместо имени** — `Дисплей для SM-G991 (S21) ориг` (profi) =
   `Дисплейный модуль Samsung Galaxy S21 (SM-G991), оригинал` (greenspark) =
   `Экран Самсунг Галакси S21 в сборе оригинал` (divizion).
9. **Лишние уточнения о комплектации** —
   `Дисплей для iPhone 12 в сборе с рамкой и тачскрином, оригинал (снятый)` (greenspark) и
   `Дисплей Apple iPhone 13 в сборе с тачскрином (Original, снят с нового)` (tgsm):
   «с рамкой», «в сборе», «снятый» — шум, а не признак другого товара.
10. **Сокращение с дефисом** — `Шлейф зар-ки айфон 11 копия` (divizion) =
    `Charging port flex iPhone11 Copy AAA` (liberti).
11. **CAPS LOCK + внутренний код детали** — `БАТАРЕЯ ХУАВЕЙ П30 ЛАЙТ (HB396286ECW) копия`
    (divizion) = `Аккумулятор Huawei P30 Lite (Копия)` (tgsm) = `Battery P30 Lite Copy AAA`.
12. **Двойной пробел и длинное тире как разделители** —
    `Дисплей  Samsung Galaxy A52 (SM-A525) — копия` (tgsm).
13. **Множественное число в названии позиции** — `Крышки задние для iPhone 15 оригинал`
    (profi) = `Задняя крышка (стекло) Apple iPhone 15, оригинал` (greenspark). Слово «стекло»
    здесь — часть описания крышки, а не тип детали «стекло»; матчинг не должен уводить
    позицию в группу защитных/дисплейных стёкол.
14. **Слэш и две модели в одном названии** — `Дисплейный модуль Poco X3 NFC / X3 Pro, аналог`
    (greenspark) при `Дисплей Xiaomi Poco X3 в сборе с тачскрином (Копия)` (tgsm) и
    `Экран Поко X3 в сборе копия` (divizion).
15. **Ловушка «стекло дисплея» vs «дисплей»** — `Стекло дисплея с OCA Apple iPhone 14, аналог`
    (greenspark) и `Стекло дисплея Apple iPhone 13 (Копия)` (tgsm) содержат слово «дисплей»,
    но это отдельный тип детали (`glass`), а не дисплейный модуль. Аналогично
    `Стекло для переклейки iPhone 13 ориг` (profi) и `Glass iPhone13 (OCA) Copy AAA` (liberti).

## Манера именования по магазинам

Каждый магазин пишет названия по-своему — это и создаёт основную сложность матчинга.

| Магазин                              | Стиль названий                                            |
| ------------------------------------ | --------------------------------------------------------- |
| `tgsm` — ТГСМ, taggsm.ru             | Формально, бренд полностью: `Дисплей Apple iPhone 13 в сборе с тачскрином (Original)` |
| `profi` — Профи, siriust.ru          | Через «для», класс качества сокращённо: `Дисплей для iPhone 13 + тачскрин ориг`        |
| `liberti` — Либерти, liberti.ru      | Латиница, модель без пробела: `LCD iPhone13 + Touch ORIG`                              |
| `greenspark` — ГринСпарк, green-spark.ru | Технично, с модельным кодом: `Дисплейный модуль Samsung Galaxy S23 (SM-S911), оригинал` |
| `divizion` — Дивизион, divizion126.ru | Разговорно, кириллицей: `экран айфон 13 в сборе ориг`                                  |

## Что проверяет тест

`backend/tests/integration/test_demo_fixture.py` (маркер `integration`, БД не нужна):

- файл существует, валиден как JSON-массив, размер в диапазоне 250–400;
- у каждой записи ровно набор из 12 полей;
- `store_slug` только из пяти допустимых, представлены все пять;
- `(store_slug, source_sku)` уникальна;
- `price_retail > 0`, формат десятичной строки с двумя знаками; `price_opt < price_retail`;
  `price_old > price_retail`; есть и заполненные, и `null`;
- `stock_status` только из допустимых, присутствуют `in_stock`/`low`/`out`/`preorder`;
  `stock_qty` — `null` или неотрицательное целое;
- `url` ведёт на домен своего магазина, `image_url` абсолютный;
- каждое название разбирается в тройку «устройство + тип детали + класс качества»
  (нормализатор в самом тесте — исполняемая спецификация ожидаемой кластеризации);
- покрыты все 16 устройств, все 8 типов деталей, все 4 класса качества;
- есть минимум 20 позиций, представленных в **3+ магазинах**, и хотя бы одна — во всех пяти;
- внутри такой группы названия попарно различаются и цены не совпадают;
- все 12 ключевых «трудных» названий на месте;
- цены дисплеев и аккумуляторов лежат в реалистичных границах.
